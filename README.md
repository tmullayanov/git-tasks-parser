# git-tasks-parser

CLI-утилита создаёт один Excel-отчёт по всем коммитам, достижимым из выбранной ветки одного или нескольких Git-репозиториев. Обычные слияния включены; коммиты из ещё не слитых веток исключены.

```powershell
uv sync
uv run git-tasks-parser --repo C:\work\api --repository-name backend --repo C:\work\web --main-branch main --timezone Europe/Moscow --output C:\reports\commits.xlsx
```

Если зависимости уже установлены, программу можно запустить без сборки пакета: `uv run --no-sync python main.py --repo C:\work\project --main-branch main --timezone Europe/Moscow --output C:\reports\commits.xlsx`.

Параметр `--repo` обязателен и может повторяться. `--main-branch`, `--timezone` и `--output` также обязательны и общие для всех репозиториев. Необязательный `--repository-name` должен стоять сразу после соответствующего `--repo`; иначе имя берётся из директории репозитория. Пустые и совпадающие без учёта регистра имена отклоняются. Короткое имя ветки означает локальную ветку (`refs/heads/main`); для remote-tracking ветки укажите полное имя, например `refs/remotes/origin/main`. Утилита использует локальное состояние Git и не делает `fetch`. Существующий файл результата не перезаписывается.

В отчёте один лист с колонками `Commit hash`, `Issue key`, `author email`, `Commit date`, `repository name`. Для каждого уникального ключа задачи в полном сообщении коммита создаётся отдельная строка. Коммит без ключа тоже получает строку с пустым полем `Issue key`. Ключи распознаются в верхнем регистре по шаблону вроде `PROJ-123` или `MAIN_2-4`. Строки сгруппированы по порядку `--repo`; совпадающие hash между репозиториями сохраняются.

`Commit date` берётся из даты коммитера и переводится в указанный пояс IANA. Excel хранит его как дату и время с секундами, но отображает в формате `YYYY-MM-DD HH:MM`. Остальные значения записываются как текст, включая строки, начинающиеся со знака `=`.

